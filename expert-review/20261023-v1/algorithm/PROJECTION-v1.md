# Finite operational projection

This defines the runtime fields of this particular algorithm. It is not an AST interpreter, a compiler, or a source-counter oracle. The exact finite declarations are enumerated in SOURCE-INDEX-v1.tsv, with their bodies in PROCEDURES-v1.md and the five released constructor/selector/properness/agreement/tree data files. ACCOUNTING-READ-SITES-v1.txt records the exact original module/line occurrences of the accounting fields and functions mentioned here. The mathematical counter C is external analysis of this runtime execution.

|recursiveWork|ForestReceipt, ChildrenReceipt, CommonReceipt, MeterReceipt and scheduler receipt wrappers: read only into accounting totals|

|callerWork|MeterReceipt/source scheduler receipts: read only into accounting totals|
|administration|ScanMeasured: read only into scan accounting recurrence|
|prefixWork / forestDebit|PaidCurrentSource.CurrentReceipt and PaidRequestsSource.PaidExecutionReceipt: read only into final accounting aggregations in PaidBestSource, PaidRequestsSource and current-query accounting|

The exact record declaration, not a substring match, determines a field. In particular Child.paid, Entry.budget, resolved Job.cost, additionalCost, knownCost, allocated budget, pending count, partition/source-cut/component lengths, colors, labels, ownership, modes and every comparison operand remain runtime data. Rule4 Branch.cost is the actual method length(b.cuts), not a cached field; each retained occurrence traverses it. No field is replaced by dummy zero. Omitting a field changes the runtime record's arity; retaining a field allocates and computes its real value.

Retain checks, tailSizes, comparisons, calls, queries, visits, sourceCuts, partition, outputs, refusals, visited, childAttempts, pruned, colored trees and groups, setup computational selections, literal geometry computational selections, optimizer trials/selected/output/recoveries, and all answer/candidate/branch fields. A caller discarding a returned reference does not reclaim its allocation. There is no GC. Stored calls/queries lists retain the exact source concatenation order even when it differs from physical call order.

There is one explicit representation projection in addition to omitted fields: when a projected wrapper has exactly its computational `value` field left, return/store that value directly rather than allocate a one-field wrapper. Thus Charged/Measured/SourceExecution-like single-value wrappers unbox, whereas BestMeasured(value,checks,tailSizes,comparisons), ChoiceMeasured(value,checks), ForestReceipt(value,calls), ChildrenReceipt(value,calls,agreementChecks) and every other multi-field receipt remain actual allocated records. Constructor/projection for an unboxed wrapper becomes the same value word with a paid return/copy; it does not invoke another computation. This projection preserves the entire remaining field by the identity map and preserves all decision/callback events. It is not an unspecified diagnostic deletion. Source record layouts in the appendix are interpreted through this declared representation, not silently as machine records with dummy analysis words.

Remove the analysis-only parameters `W:OrdinaryWork`, `w:Nat->Nat`, `fee:ForestQuery->Nat`, `agreementFee:Forest->Nat`, `classFee:CheckRequest->Nat`, `literalFee:LiteralCall->Nat`, checkFee and analogous printed numeric fee parameters. A parameter's result may only feed the omitted fields above. The runtime signatures in ALGORITHM have no such argument. `actual`, `ordinary`, `rec` and scheduler `f` ARE NOT deleted answer parameters: their exact fixed bindings are below.

The ACCOUNTING-READ-SITES index, together with the original enclosing declaration headers in PROCEDURES, is the finite per-routine omission list. It includes the complete accounting expression text rather than replacing it by an unspecified cost. Each occurrence is omitted only in the accounting field/argument context just enumerated. The same length/count expression written in a retained value or guard stays executed at that position. For example BEST_CUT still computes every tailSizes length and every comparison pair, whereas its discarded work formula's repeated lengths are omitted; NoOne's guard length remains, but the separate length occurring only in its discarded work formula is omitted.

A let-bound computation used exclusively by these accounting contexts is omitted together with its binding. This finite liveness rule is applied only to the displayed definitions and read-site list, not to unknown procedures. In particular a function that returns a component count used by a guard is retained even if another caller uses the same function only for accounting. A value-producing eager let is not removed merely because a later branch ignores its answer: both selector orientations, all four Early selections, all eager guard components, Rule4 state before affordability, current candidate then full best tail, and all paid output candidates retain their original evaluation order.

## Fixed answer bindings

`FastOrdinary.solve r U V` at a recursive value occurrence is QUERY(r,U,V). Its direct recursive position in COMMON is permitted only after the written strict leaf-count test. `cutoff FastOrdinary.solve parentBudget` and ActualCaller.actualCallback(parentBudget) are PAID(parentBudget), which tests r<parentBudget before calling QUERY. Each `actual`/`ordinary`/`cb` parameter of child, Rule4, Rule5, Hard2, grouped, disjoint and generic-forest bodies is this fixed PAID closure inherited from the current ordinary query. The generic forest solver recursively calls FOREST with the same closure and a smaller forest budget. No callback is an externally supplied oracle.

The scheduler callback adapters are the finite bodies in OrdinarySchedulerSource, GroupedJobsSource, OutputRun, QueryCaller/ForestDefs and their literal variants. They build actual local targets/source forests, test affordability, execute FOREST or PAID at the displayed computed budget, and return their actual component-cost/answer pair. Numeric cost components in such a returned pair are decision data and remain. `cost` and `valid` in the finite best routines bind CutCost/CandidateValid, actual forest length/additionalCost, and the exact shown predicates, never an arbitrary runtime function.

## Preservation argument

The observation is the retained return data together with the sequence of actual value-producing ordinary/forest callback occurrences, including their arguments, budget, result and lexical occurrence identity. It also includes every branch condition and candidate-producing local computation. Source-counter/debit expressions are mathematical observations of these occurrences, not another execution whose pure callback probes are physical events. We do not assert that executing every analysis expression naively would have the same physical calls.

Prove preservation simultaneously for the finite procedures by induction on their evaluation derivations, with the outer well-founded rank `(ordinary budget, leaf count)` and inner forest budget/list/tree structural rank. In a primitive/constructor case the retained arguments and discriminator coincide; the projected constructor stores exactly those data fields. Numeric work arithmetic and proof objects have no retained consumer, so omitting them changes none of these arguments. A record projection selects the same retained field. A source accounting-field projection has no runtime consumer and no runtime event.

For a sequential let whose value is retained or used by a branch, apply the induction hypothesis to that exact body, retain its observation, bind its identical projected result, then continue; this proves left-to-right concatenation of actual events. For a work-only let in the finite table, the value has no edge to a retained field, branch, or value callback argument. Its removal therefore contributes no value event and changes no subsequent retained binding. The read-site list exposes all such edges; analysis arithmetic is never used as a decision dependency. This is liveness of the listed data graph, not an assumption of a desired runtime bill.

For an if/match, the condition/discriminator is retained and identical, hence the same case executes. Both eager branches' preceding lets remain; short-circuit bodies invoke their second thunk only in the original case. List recursion concatenates the same head/tail event sequences in the body-written order. In Rule4 the tail observation comes before state/current callback; in children and bothBad execution the current callback comes before tail; the retained trace-list constructors remain separately in their written order. Equality of physical order is obtained from these evaluation rules, not from a trace-list chronological interpretation. Duplicates are distinct lexical/indexed occurrences and are never coalesced. Refusal and callback failure stop at the same test and retain the same prior observations.

At an actual recursive callback the binding above evaluates the same cutoff, arguments and budget. The appropriate smaller-rank induction hypothesis gives the same answer and internal sequence; append that one occurrence and continue. An equal-budget non-COMMON callback is refused on both sides and contributes no recursive query. COMMON's same-budget call has strictly fewer leaves; an overlap forest recursion has positive d and decreases q. A failed guard/affordability or malformed input takes the identical refusal path.

The proof applies to the exact finite field/consumer inventory, including BestMeasured/ChoiceMeasured diagnostics, all Setup/LiteralGeometry data selections and their executed tests, scheduler resolved costs, Hard2 modes, colored recovery receipts and optimizer trials. Thus projected QUERY returns the ordinary value of the named complete step with its canonical recursive binding. Pointwise value correspondence to canonical FastOrdinary.solve is the well-founded simultaneous induction using these same body cases and the supplied functional interface; the subsequent source-counter occurrence/sum coupling and local/global cost bounds remain separate mathematical obligations. No exact-C runtime output is introduced.

Proof-valued fields do not require a runtime evidence constructor. Their listed full propositions serve to state correctness of executed guards. They are not pattern-matched to choose computational fields. Setup/ofProps exact data selections and guard prefixes are supplied independently of evidence values; FirstChoice executes Priority/LocalGuard tests before selecting raw data. Consequently the projected data constructors preserve their computational selections and cases. This does not replace a logical proposition by True or assume an admission oracle.
