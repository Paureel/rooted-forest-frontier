# Reading or rebuilding the formal appendices

All included `.lean` files are source copies; `.olean` caches, native runtimes and machine-specific environments are omitted. `SOURCE-MAP.json` records exact bytes and original relative origins. `CONTEXTS.json` preserves the distinct ordered module providers, roots and each resolved module. No same-name pool flattening is permitted. `BUILD-ORDER.json` is a static topological import inventory, not a claim that a new build passed.

The contexts cover the functional query/optimizer, explicit SOURCE bound, runtime graph/value/position interfaces, and separately authored functional/SOURCE assembly. Module imports can include historical definitions and other unused statements; presence in an import is not evidence that every statement was used by the selected theorem. Original used-constant audits identify the load-bearing roots and excluded old shortcuts. Standard imports Lean/Std/Init/Lake belong to the pinned Lean 4.35.0 distribution; no project module is replaced by a dummy axiom or interface stub.

For a clean rebuild, a reviewer can install the pinned standard Lean distribution, create a distinct output directory for every listed provider pool, and compile each context's ordered modules with `lean --root=<source-pool> -o <output-pool>/<module>.olean <source-file>`. Set LEAN_PATH to that context's output pools in the exact recorded order and the normal toolchain libraries. Create subdirectories for dotted module names. Reuse a built module across contexts only if its source AND resolved imported providers match; matching a source filename alone is insufficient. Keep contexts isolated if unsure.

Compilation is optional reviewer work and may take substantial time. This package does not auto-launch it or install software. All previously executed checks remain the original retained receipts; a fresh full-corpus rebuild has not been asserted. A rebuild checks the formal component proofs and printed axioms. It does not automatically check the mathematical prose that connects projected execution, concrete operation counts, allocation/width bounds and actual RAM bills. An end-to-end formal version of that bridge is still the separate certification task.

The original local project used resource-limited Lean invocations. If a reviewer elects to replay the corpus, use suitable local time/memory controls and preserve failures. No network service or original absolute workstation path is required by the project source imports supplied here. Absolute paths appearing in comments or historical receipts remain provenance only.
