# Finite retained Nat declaration/site catalogue

## Scope, identities and meaning of a bound

The computational inputs to this catalogue are the frozen `math_pseudocode_v1` appendix, DATA packets, algorithm, representation and full logical TYPES, and the deletion-only `math_projection_amendment_v2`. The sole supplemental supply is the separately licensed exact standalone TYPE `METER-RECEIPT-TYPE-v1.json`, whose fields already match the displayed runtime constructors. The named root draft `MATHEMATICAL-SCALAR-CATALOGUE-DRAFT-v1.txt` supplies a proposed conclusion. No new supporting body, peer proof, review outcome or runtime experiment is used. Original module/line below is an identity in `SOURCE-INDEX-v1.tsv` and `CONTEXTS-v1.txt`, not an assertion that the module name is a Lean namespace. The full source/object pins in the v1 source binding remain controlling. `RMAF.partitionCheck` is the RMAF declaration, and the actual rooted-tree primitive is `RMAF.rootedSpan`.

Let **U** here mean the total number of actually executed abstract elementary operations after the decoder, including calls, frame/environment construction, field accesses, traversals, diagnostics, failures, optimizer trials and the one recovery. It does not mean the raw input word, denoted **raw** below. Each actual counter increment, traversal step, constructor or event we charge is accompanied by at least one such operation. No source `work`, semantic bill, hypothetical search-tree size, allocated-cell count or callback replay substitutes for U. The invariant for a prefix may use the completed execution's U by monotonicity; a stronger prefix version uses the prefix's actual operation count.

Let M0 be the maximum original input label, with M0=0 if taking a maximum over an empty auxiliary list. For valid raw binary trees, M0<2^L with the representation's actual input-label width bound L>=1. Let G be the number of executed fresh-marker arithmetic assignments, so G<=U. Define:

* label envelope A=M0+2G, bounded by 2^L+2U;
* initial/ordinary/forest/trial budget envelope Bq=max(Q,N-1), bounded by Q+N;
* count envelope V=N+Q+U+1;
* a conservative live count-expression envelope E=4(V+1)^2.

The `+1` and constant4 in E cover intermediate sums and increments as well as final values; no arbitrary iteration of squaring is permitted. The site map below explains every retained arithmetic producer. Q bounds the original external query budget. If Q is also defined to bound all optimizer trials, use Bq<=Q. Without that convention the draft's blanket `<=Q` statement needs the displayed Bq correction; the final R=N+Q+L+2 is unchanged. Auxiliary generator inputs require their own rows: the cheap probes use fixed3, and recovery constructs length(P)-1 before its later leaf cap. Neither requires a <=Q claim. No bound q<=the current reduced leaf count is used.

Pointers and next-free addresses have a separate class P and the root's separate H0+F*U obligation. An address carried in a natural-word register is still P. The fixed `+1/+2` address preparations are not a counterexample to the nonpointer assertion. Trees, paths, forests, tables, frames and receipts are actual immutable pointer structures, never scalar encodings of their contents. An unfolded traversal of a shared tree is counted each time it runs.

## Additive counters and disjoint execution regions

For one actual plain/RW generator invocation define three finite sets of **dynamic occurrence identities**, using the activation identity and lexical branch/child position. Vevents contains each actual step invocation; Aevents each actual attempt invocation, including root/duplicate/whole-source refusals; Pevents each actual invocation of the zero-fuel cutoff continuation. These identities describe this execution; they are not materialized trace lists or a second execution.

Induct on the literal `run/step/attempt` evaluation tree. A finish/refuse step contributes (1,0,0). An attempt refusal contributes (0,1,0). A successful attempt takes the single already-computed child receipt and adds one to childAttempts, so its sets are the child's sets plus its new attempt identity. The q=0 cutoff closure's actual call constructs (0,0,1), adding its new cutoff identity. A one branch takes one attempt result and prefixRoot adds the current step identity. A two branch first executes attempt a and then attempt b (both even if results or immutable inputs coincide), then combine adds their three counters once each, then prefixRoot adds the current step. Their subevaluation occurrence sets are disjoint because they have distinct parent-child positions. Thus the stored counters equal the cardinalities of these respective sets. Every event performs at least one actual elementary operation, giving each count<=U and the sum of the three counts<=U when event charges use their distinct local operations. The weaker independent bound each<=U is sufficient here.

No reached combine site receives `(r,r)` from one execution: CoreProgram.step:114–115 and RWLocal.meterStep:95–96 each compute two actual attempts. No counter aggregation occurs in generatedOutputsMeter, appendOutputsMeter, bothBad probe reuse or wholeOutputsMeter: those select/append output lists, not receipt counters. Reusing an immutable output or a locally saved receipt field does not count as another execution. There is no scalar-doubling feedback path. Identical source argument values can cause repeated executions; those have distinct occurrence identities and are included in U.

For one actual scheduler run, visits counts the reached local job positions up to and including the first failed hard job. Empty gives0, failure gives1, and each resolved/successful hard job adds1 to the one actual tail result. Positions are disjoint, even if problem values or stored answers coincide. The same argument applies separately to plain run, runSourceMeter and literalRunSource. The surrounding schedule wrapper either returns visits0 on initial refusal or copies the one run's visits, including when final acceptance rejects. It never adds recursive solver visit counts into this local field. Hence visits<=actual reached-job operations<=U. Calls and queries store the actual budget at the same positions; their list lengths also have real construction/traversal costs.
