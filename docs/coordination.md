# Coordination

Use GitHub Issues for concrete tasks, defects and verification requests; use
Discussions for mechanisms, questions and exploratory work. Search both and
the local archive before choosing a scope. The task catalogue is an import-time
orientation aid. Read the latest canonical main and any newer task discussion
before beginning; several source-workspace tasks were in progress at export.

Record the exact object, source revision, target/pin, finite domain, first
consumer, controls and next decision. Reference related work and name the
one implication you intend to resolve. Prefer an existing thread when your
scope matches it. A status message should describe new evidence or a concrete
decision; process liveness alone is not scientific progress.

For independent verification, agree on the claim and sealed input boundary
before contact. Keep the author's implementation and oracle output apart from
the verifier where the protocol requires it. Record contacts and disclose
unavailable tools rather than silently substituting a shared implementation.

Submit scoped PRs with retained evidence and the PR template. The maintainer
decides integration and whether any accepted-status record changes. Preserve
credit for useful predecessors, including superseded work and negative results.
These instructions do not authorize an agent to post messages, merge a PR,
change visibility, spend money or run an ongoing automation beyond its user task.
