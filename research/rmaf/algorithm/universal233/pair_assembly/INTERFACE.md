# Pair-case consuming interfaces

All new theorem names are in `Universal233.PairAssembly`.

| Actual consumer | Exact result |
|---|---|
| `hard_parent_embeddings` | Literal original residual hard2 components give actual source pairwiseEmbeddings |
| `side_input_color_count` | Whole-source keep-A/split-B/keep-C color has exact cardinality4 from actual source partition and two nonempty B sectors |
| `side_output_clear` | Every literal B output block is inside one mutual-clear sector and hence clear of original A |
| `selected_edge_good_parent_core` | Actual G edge + E hypotheses give a no-larger actual agreement F', actual generated Q, original cut realization, source validity/refinement/budget, kept good A, cardinality4 and mass c^-3 |
| `vertex_pair_cover`, `vertex_pair_three_mass` | Original F is covered by the same literal two-call output list, with mass c^-3+c^-4 when either shared parent has three regions |
| `proper_pair_from_partition` | G's executable proper-input guard follows from original source partition, target labels and proper target |
| `side_outputs_descendant` | G's actual descendant-list color is exactly the restricted-subtree leaf-list color used by E |
| `good_pair_cover_mass` | Total actual `choose`/generate branch; combines literal output coverage, replacement-witness validity and same-list mass |

E's retained source-P/A-good/outside-clearance hypotheses are not inferred from a favorable local cost profile. The proof never calls original F an output refinement witness after exchange. `OutputWitness` is the frozen conclusion-only source-forest record; Q is not automatically an agreement forest. `ChoiceProgress` records vertex clearing or edge-sector clearing and the kept rooted-good A block, not a runtime promise.

Every proof body is unchanged; source and copy hashes are retained. The earlier cut Coverage name adapter is already frozen in assembly-completion. All original files remain untouched.
