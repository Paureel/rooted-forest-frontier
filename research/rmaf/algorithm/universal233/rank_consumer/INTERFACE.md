# Classifier interface

All names are in `Universal233.RankConsumer`.

| Consumer | Actual theorem |
|---|---|
| Fixed actual generate probe accepts iff rank feasibility | `probe_nonempty_iff`, `probe_empty_iff`, `accepted_iff` |
| Literal accepted output is stable at every budget | `accepted_literal_stable` |
| Rejected core has stronger all-output cost and mass | `rejected_cost_mass` |
| Concrete binary caller supplies known rank4 and executes literal q3 | `four_accepted_iff` |
| Actual optimized generator preserves the entire output LIST | `optimized_four_exact` |
| Concrete rejection has all costs>=4 and mass<=2c^-4 | `four_rejected_high` |
| Fixed generate source-model envelope with supplied rank argument | `probe_model_work`, `four_probe_model_work` |
| Exact actual optimized branch value/callbacks/model bill | `meterOptimizedFour_value`, `meterOptimizedFour_calls`, `meterOptimizedFour_bound` |

The generic mathematical inputRank is the exact original distinct-color count. The concrete four-color code does not evaluate it: its caller must prove that count is4 from actual original parent and sector hypotheses. The already frozen pair consumer provides that cardinality for its actual side color. This package does not claim to compose that caller or to charge an unproved future query.

The kernel proves meter/value equality and arithmetic bounds. Source correspondence is the reviewed conservative inspection contract, including its distinction from fine instruction counts. New caller setup allowance and arbitrary color evaluation are explicit further review/consumer obligations. No optimum oracle or partition enumeration is executed by the classifier.
