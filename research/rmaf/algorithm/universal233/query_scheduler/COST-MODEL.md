# Actual scheduler source model

The executable program is Caller.run and Caller.schedule. Work.meterRun and Work.meterSchedule project to those exact values by kernel theorems. The meter dispatches charge p b at the same literal p,b used by solve p b; meterSchedule_trace proves the recursive charge is the sum on that executed problem-budget trace, including failed calls and duplicate problems. No unrelated supplied vertex/problem list is accepted as a trace surrogate.

The caller envelope is 32*(number of slots+1) declared source units, plus the sum of the supplied recursive charges. The declaration table allocates 2 units to nil, 5 to a resolved slot and 8 to a hard slot. A successful slot allocates at most an answer cons and a query cons; no list append occurs. Failure stops later calls. An Option.map costs a branch and, when present, one cons; it does not traverse the answer list. Returned answers are scanned separately for the final SUM test. The lower-bill guard pays for knownCost and pending full scans even on early rejection; allocated recomputes those scans on the nonpruned branch. The model allows8n+8 early and16n+20 later preprocessing units, then the run charge and4*answerLength+4 postprocessing units. Kernel arithmetic proves the displayed32(n+1) bound.

This is a conservative source-operation contract, awaiting fresh independent source inspection. It is not an extracted fine-instruction identity. Nat arithmetic is unit cost only for bounded words; a bit model multiplies its arithmetic charges by a conservative polynomial in the bit lengths of q, slot costs and the source input. Answer payload references/conses are unit operations; copying or serializing the eventual forests/cuts requires its own output-size bill. The slot construction, actual depth-zero/one pretests, restrictions and global reconstruction are additional consuming work, not included here. Recursive charges require the future solver's own proved bound.
