# Compressed audit header cap failure

The first compressed wrapper passed its fresh exact-sink producer/value/false/pin controls, then stopped at `FreshHeader` because the complete all306 imported-module path/name header exceeded its1MiB stdout cap. No scientific producer file was consumed or newly extracted. The exception/certificate/source are retained. The wrapper guarded before saving that stdout, so its exact header stdout bytes were not retained; this diagnostic-evidence limitation is explicit. No math acceptance or mathematical refutation follows.

The v2 descendant preserves v1 unchanged, raises only the small metadata stdout cap to8MiB, always writes command diagnostics before any cap failure, and monitors free disk space and output caps while the child process runs. It sends SIGINT only to its own new process group on a limit violation. Full body output still goes directly to gzip; no raw scientific dump is allowed.
