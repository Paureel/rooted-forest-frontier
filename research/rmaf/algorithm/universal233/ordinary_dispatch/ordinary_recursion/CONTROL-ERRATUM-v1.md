The smaller crossed-quartet pilot had compiled in 4.76 seconds and produced a 2,942,024-byte binary. The combined module failure is retained as an instrument/resource failure, not a false mathematical result.

The subsequent false-control driver was launched before the positive dependency result was inspected. Its expected exit code matched 1, but its actual diagnostic was an unknown ScaffoldControls module prefix. Therefore that driver's PASS_AUTHOR_LIVE_GUARDED_COMPILE status means only expected process exit; it is NOT accepted as mathematical control evidence. This was a sequencing mistake. The raw receipt, log, and source remain preserved.

The next driver uses a 64 MiB per-file limit while retaining the live 3 GiB free-space floor, 30-second runtime cap, and 8 MiB stdout cap. For expected mathematical failures it must reject import, parse, elaboration-identifier, and corrupted-dependency errors. The positive dependency must complete and be inspected before the contrary mathematical claims run. The changed driver repeats its synthetic true/false/resource-stop controls before applying the actual fixture.
