# Source operations versus formal meter

This is an independent inspection of the released source programs and their cost statements. It does not turn declaration counts, compile times or an arithmetic meter into a compiled-machine theorem.

For the original caller, `QueryWork.meterRun_value` and `meterSchedule_value` prove that the declared meter has the same mathematical Receipt as `run`/`schedule`. The trace theorem identifies each actual problem/budget occurrence and the exact sum of a supplied charge at THOSE occurrences. A failed recursive call is charged. Equal problem values are still separate occurrences. Resolved work does not dispatch a solver. Our compiled readout checks these statements on the fixed controls using the explicit charge `1000*U.length+b`, so an unrelated or deduplicated trace would be visible.

The released source meter declares 8 units for a hard dispatch, 5 for a resolved job and 2 for the empty list, plus scans/postprocessing. The kernel proves callerWork≤32*(jobs.length+1) for that meter. These units are a stated source operation convention: they are not derived Lean VM/native instructions, memory allocation, garbage collection or arbitrary-precision arithmetic costs. `charge` is supplied, not an actual bound on the recursive solver established here.

The outer original program performs additional work. `prepare` runs before the scheduler prune; every visited Q block pays requested-label checks, two literal restrictions and a depth0/1 pretest. `properBlock` recomputes BOTH originals' leaves inside its per-label predicate. Charging those repeated scans is polynomial; no caching is silently assumed. `recursive` performs two MORE restrictions on every actual hard dispatch before calling the supplied solver. Returned Option/pair construction, cost lengths, additions/comparisons/subtractions and flattening of actual returned forests require charges too.

Let M include the complete original tree/Q encodings, label bit lengths and budget q's bit length. Literal list membership and repeated tree/list scans give polynomial requested-label and restriction work. The depth0/1 pretest considers only uncut/single ORIGINAL source-edge candidates, at most O(M), rather than enumerating general partitions. Each such candidate has at most two blocks. The naive leaves/rootedSpan/minimalVertices/address-comparison/restriction/sameShape operations are polynomial. Each sameShape subtree-pair has one parent-pair and occurs at most once; the four child pair possibilities do not yield duplicate routes to a pair. A conservative O(M^5) per pretest and O((|Q|+1)M^5) preparation envelope is consistent with these source bounds. This is source inspection, not a formal fine-step proof.

`flatMap` copies returned outer forest spines through append. On valid local returns under checked disjoint Q, their total number of blocks and leaf occurrences is bounded by original taxa. Inner block references can be retained; serialization/deep copying and original cut output are separate bills. Thus the conditional caller source work is a polynomial plus the SUM of actual recursive costs at their actual budgets, with restrictions/dispatch/returns included. A full O(poly(M)*c^q) recurrence still needs the recursive dispatcher, a decreasing measure, consistent polynomial potential and every other rule case. A sole hard call can keep q unchanged.

For grouped states, localTarget scans the literal target, owned scans CURRENT source references and checks WHOLE-source leaf containment, family scans supplied blocks, and concatenation copies supplied outer forest lists. With N bounding total boundary tree/list cells and b bounding Nat label bits, pessimistically charging repeated leaves/containment scans gives O(N^4(b+1)) for constructing all groups and supplied-family concatenations. Checking properness, agreement and actual piece hulls can be bounded conservatively by O(N^7(b+1)): rootedSpan/address construction, target/source pairs, restrictions and naive list membership all fit that loose polynomial. Source list filtering does not secretly construct a replacement source. CrossClear needs only cross-group current-piece pairs; within-B overlap is allowed.

The grouped universal proof does not run an exhaustive solver or enumerate local agreements. The finite15-partition child control is a test oracle only. `ResidualSolverContract` has no runtime bound and supplies no recursive implementation. The quoted conservative polynomials are mathematical source accounting consistent with the inspected definitions; no extracted machine, callback complexity, global solver runtime or smaller-base result is accepted by this review.
