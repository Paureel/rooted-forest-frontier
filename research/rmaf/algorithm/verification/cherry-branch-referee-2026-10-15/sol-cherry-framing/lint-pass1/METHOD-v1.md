# Review method

The permitted task is a fresh-context framing review of the named ordinary cherry release and sealed review. The reviewer first read TARGET-v1.md, wrote REVIEW-SKELETON-v1.md, then read referee-sim and prose-lint in full. Reading-contract, independence-bookkeeping, tool-stewardship, timing-discipline, the toolkit index, and the emitall guide govern the evidence checks. The reviewer did not author the input documents and received no author, child, or other-reviewer discussion.

The source of mathematical conclusions is the sealed review; exact theorem signatures and a few executable definitions are inspected only to resolve named framing questions. New checks cover file identity, manifest membership, quoted line ranges, receipt counts and arithmetic between those counts. They do not execute Lean, reconstruct a proof, replay the independent graph instrument, run a solver, or revalidate scientific producer data. Zero new mathematical replications are claimed.

The one-shot local Python check is justified because emitall checks declarative receipt claims but does not by itself bind file-manifest payloads together with literal line-range quotations. Standard pathlib, json and hashlib operations suffice; no reusable scientific instrument is added. Failure means a wrong pin, path, byte count, quotation, duplicate path, receipt unit or expected count. Before reading real manifests, the same row comparator must accept a synthetic clean row and reject corrupted bytes, a corrupted hash and a corrupted size. An exact-quotation comparator must accept its clean fixture and reject an altered quotation. These are document-check controls and confer no mathematical independence.

The bounded run reads only the two named manifests and their listed bytes for integrity, plus explicitly listed reading inputs for quotations and receipts. Hashing a listed file does not entail reading its implementation as evidence. Runtime is initially unknown and will be measured on this bounded job; no long run or extrapolated runtime is proposed. No source or olean is copied, and no frozen input or skill is edited.

The two prose passes include honesty and number checks, parse/composition, pattern checks, a sentence-level colleague read, openings/tables/conclusions, and a separate cold summary. The report and companion will be checked as rendered plain Markdown text; no PDF or TeX rendering is involved. Both passes are by the same reviewer. The prose-lint rule requiring a different editor after a rewrite remains a root integration requirement, and this self-review is not credited as that different-editor pass.
