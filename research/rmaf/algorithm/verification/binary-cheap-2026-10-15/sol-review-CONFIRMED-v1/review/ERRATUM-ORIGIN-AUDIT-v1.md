# Producer-origin audit erratum

The previously shared all-origin auditor enumerates the merged Lean environment and assigns each constant name to `getModuleIdxFor?`. That procedure inventories one resolved entry per name. It does not inventory every declaration occurrence stored in every producer module. Lean permits multiple modules to emit the same-typed theorem and can retain one resolved name/origin when importing them together. This correction scopes the older all-origin wording; the frozen 90/213/109/36 records and archives remain unchanged.

The binary-cheap merged environment contains 3590 distinct names. The 102 stored producer arrays contain 3616 declaration occurrences, including 26 extra occurrences across 23 repeated-name groups. Both views contain 339 private entries. The standalone restriction/embedding pair contains 96 entries (38+58); comparing it with the 83 entries attributed to those modules in the combined environment was an invalid denominator comparison. The generated RMAF equation theorems account for that thirteen-entry difference. The failed comparison and its original assumptions are retained.

A Lean/Std-only plant made the difference executable. ProducerToyA and ProducerToyB both emit the same two True theorems. ProducerToyBad emits an axiom with one of those same names and the same type, plus another shared theorem and one own clean definition. The merged view resolves the shared axiom name to the earlier theorem and falsely accepts ProducerToyBad as standard-axiom-clean. The stored ModuleData audit retains the actual axiom declaration and rejects it. That audit also catches the previous unused, private and foreign-axiom controls and rejects missing/duplicate producer occurrences. Its 21 control checks passed before the complete scientific producer audit.

The corrected audit reads each `Environment.header.moduleData` constant array before name coalescing. It records producer module and resolved origin separately, checks every own ConstantInfo kind, and collects axiom dependencies from that occurrence's actual type and body. All 102 scientific producer modules passed, with no direct custom axioms and only the three allowed standard axioms in the observed closures. A normalized type/value comparison also passed for all 96 standalone restriction/embedding entries. Source adapters remain exact: the restriction file changes only its filename, and Embedding changes only the registered first import. No candidate proof or mathematical fixture changed.

Of the 78 scientific modules in the accepted good-parent review, 71 have identical source bytes in this newly audited 102-module closure. The other seven are old control modules absent from the binary-cheap closure; they were not newly audited. This review therefore does not silently promote the whole old review to a new producer-level audit. The exact overlap is retained in prior-review-producer-audit-coverage-v1.json. This correction is the same checker lineage and adds zero independent replications.

Source/API locators: native Lean 4.35.0 `Lean/Environment.lean` ModuleData lines109–129, header lines142–176, theorem coalescing/subsumesInfo lines2252–2300, producer data/import merging lines2314–2360; `Lean/Util/CollectAxioms.lean`. Reproduction sources, frozen toy expectations, failed diagnostics, merged and producer inventories are included in this review.
