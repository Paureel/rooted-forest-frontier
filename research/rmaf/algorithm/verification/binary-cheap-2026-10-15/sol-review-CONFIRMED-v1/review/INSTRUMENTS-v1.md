# Review instruments

These are one-shot, source-pinned review instruments. They are local because the task owns this review directory and its exact frozen inputs. No toolkit package was changed and no workspace-wide bootloops-check run is claimed. Every Python execution used ./bootloops-python; native compilation used the recorded Lean4.35.0 executable.

prepare_sources.py checks the released280 entries and original/canonical/import pins, then extracts only source files into an empty build directory. build_sources.py performs the measured two-module pilot followed by the fixed100-module remainder. Source originals and admitted adapters are retained separately. run_observer.py compiles reviewer observers and preserves logs/source/binary identities. Failed initial helpers and generator versions are historical records; replay the final src/*.lean files rather than regenerating them with a superseded make_* draft.

compare_readouts.py compares native G/probe/classes/budget/list/hull/refinement/local certificate/mass observations with unchanged READY values. The reference is the disclosed own X0 graph/generator/oracle lineage. The oracle enumerates only the frozen three-leaf local partitions; it is not part of an algorithm. final_control_checks.py extracts the exact pure READY comparator functions without executing its top-level writer, then applies them to native output lists/masses and corruption twins. Never deduplicate the list or omit internally overlapping target B pieces.

The original OriginAudit.lean enumerates a merged environment. It remains useful for name-resolution diagnostics but is insufficient for an every-producer audit. ModuleDataAudit.lean reads each stored producer constant array, retains repeated names in different modules, checks each own ConstantInfo kind and its actual type/body dependencies, and records the resolved origin separately. compare_module_data.py requires every module array/count/name pair, standard axioms, and no duplicate occurrence within a module. The21 toy controls include a coalesced custom axiom missed by the older rule; the scientific104-check result is the required final producer audit. See ERRATUM-ORIGIN-AUDIT-v1.md.

FingerprintSupport.lean records exact type/value representations after the registered alpha/private-name normalization. Its initial implementation and failed true twin remain preserved. The final v2 normalization removes only binder names, preserves de Bruijn indices and all other expression content, and maps private constant/projection names to user names. Seven Lean/Std-only controls pass, including same-body module twins and changed-body rejection. compare_producer_v4.py is the final successful adoption comparison; v1–v3 retain syntax/normalization/denominator failures. The primary adapters are literal source comparisons, not fingerprints alone. Supplemental fingerprints add no independent replication.

runtime-value-dependency-summary-v1.json records binders and definition/opaque value dependencies, stopping at theorem proof bodies. It supports an input/dependency separation statement only. It establishes no source-operation, compiled runtime or capped-query charge bound. actual-imported-dependency-identity-v1.json records the installed library and fresh local import identities; installed standard libraries were not rebuilt or reviewed.

final_integrity.py rechecks all448 prior snapshot entries/four archives, all280 author entries, all102 current canonical source files and required completed receipts. Scientific fixture expectations never change. The final immutable package includes the current review, unchanged READY reference snapshot, all released author files, and hashes for omitted fresh compiled binaries. To rerun, use a writable copy in the pinned workspace with the recorded native runtime; no outside compute or hidden optimal-F input is required.
