# Bounded evidence check

The check below authenticates only the sealed reports and named source/receipt records used in this framing review. A mismatch in either root manifest digest, any selected file digest, declared count versus parsed record count, source snippet, or named declaration presence is a failure. It does not replay Lean, re-audit all modules, validate a runtime theorem, or provide independent mathematical replication.

Before reading the real files through the checker, test SHA-256 on the standard empty and abc messages; require their known digests, then require a one-byte-corrupted abc twin to fail the original digest. Require a two-record synthetic parser example to retain both records and a wrong expected count to reject. The controls test byte comparison and parsing only. The sealed reports were already read before this check was designed, so no claim of precontact scientific acceptance attaches to these controls.

The toolkit index and emitall guide were read. Emitall re-emits numerical receipt fields; this check also authenticates selected files against two differently shaped manifest maps and records exact source snippets, so a one-shot standard-library script is used for these local metadata facts. No shared instrument is being added or repaired. Runtime is unknown and will be measured; no long run, solver, fresh compilation, or full validation suite is planned.

Python runs through the project launcher with BOOTLOOPS_MONITOR_DISABLE=1. The launcher's documented uninstrumented option prevents writes outside the assigned directory. All receipts, script output, and generated hashes stay here.
