# Actual source operation review

The local executable definitions admit the stated O(N^7) aggregate source-operation envelope, and therefore the permitted O(N^8) envelope, with a polynomial scalar label/budget bit factor. One row in frozen SOURCE-WORK.md needs qualification: its pendantPartition explanation omits repeated cut construction inside the root-complement filter. Using the document's own coarse O(N^6) cut bound gives a conservative O(N^7) bound for this row. The aggregate survives. This does not assert that O(N^7) is tight or refute a sharper bound proved by a different analysis. It is a source inspection argument, not a kernel fine-operation polynomial theorem or compiled-machine runtime proof.

Let N be one plus all T/S constructors. Lists contain at most O(N) vertices, labels or cuts; address lengths are at most N. Cherries and vertices retain all mapped original addresses and every append/list copy. Conservative O(N^3) for cherries, vertices and a leaf search covers these traversals. RMAF.rootedSpan explicitly builds root-prefix lists; RMAF.minimalVertices can recompute rootedSpan at every constructor. The stated O(N^3) and O(N^4) bounds respectively allow all membership scans, intermediate prefix maps and copies. Executable.pendantOriginal filters all original vertices and recomputes the actual minimal hull twice per vertex, then scans address lists with O(N) cell comparisons; its O(N^6) bound includes rejected vertices and unsuppressed paths. Selector.candidates maps every actual target cherry, materializing every such full cut list, so O(N^7) includes all rejected candidates before the priority scans. The three find scans and fallback head fit O(N^3), including list length scans.

Ordinary.coreLabels is `(leaves S).filter fun x => !((cuts S a b).map (subtreeLabels S)).flatten.contains x`. The call to cuts is inside the per-leaf closure. With no source-level let hoisting assumed, the coarse O(N^6) cut bound is incurred for each of O(N) labels. Mapping all subtreeLabels and flattening costs at most O(N^3) per such evaluation, so coreLabels and therefore pendantPartition have the conservative O(N^7) bound. Even if the Lean compiler hoists invariant work, that optimization is unnecessary for this envelope and is not assumed. The frozen row's O(N^4) accounting covers the listed subtree/map/flatten/complement work once cuts have been materialized outside this filter; the actual definition does not state that sharing. A sharper row bound needs its own argument. Recomputing pendantPartition for a constant number of local branches remains within O(N^7).

Selector.makeChild constructs the actual P and `P.filterMap restrict`. Once P exists, at most O(N) restrictions each scan the original S and selected membership masks; all newly allocated tree constructors and list cells fit its O(N^4) allowance. Singleton partitions/terminal searches/materialization fit O(N^4), including both endpoint children. remaining performs the actual paid<=budget comparison before subtraction; childCall binds the concrete supplied solver only after success. Boolean and scalar operations converted to bit work incur a polynomial factor in label bit length and log(k+2). The O(N^7) aggregate includes validation if an outer caller checks original proper/equal labels; raw constructors themselves do not validate those hypotheses.
