# Additional prerelease private-coalescing control

This separately versioned extension preserves all original controls/results. Before execution: two Std-only files have the same source basename SamePrivate, separate source directories, and a first private declaration `BlindPrivateTwin.shared : True`. One stores a theorem, the other an unused axiom plus its own clean theorem. Compile each in its own source directory, preserving all outputs, then copy their newly built oleans under distinct import filenames in one isolated control-only directory. ModuleData has no stored module-name field; this should make their actual private constant names identical while producer import identities differ. This last sentence is a design hypothesis to test, not an assumption for acceptance. If the names do not coalesce or import is refused, preserve that failure and mark the fixture missing rather than silently relaxing it.

Expected: the clean twin alone passes and contains a true private theorem with a body. The combined environment stores two occurrences with exactly the same private name and type, one theorem and one axiom; the merged resolved entry is a theorem. The producer gate must reject the hostile private axiom, despite an own clean declaration. Exact type strings are compared, both producer identities retained, and no original/candidate olean is loaded. This closes the control corner where private, unused and coalesced are simultaneous, beyond the already passing separate private/unused/coalesced controls.
