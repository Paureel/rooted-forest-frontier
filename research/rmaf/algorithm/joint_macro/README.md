# Joint edge ownership development instrument

This route wraps the existing X0 partition/span and source-predicate code for
development of simultaneous source-component splitting. It adds a cut-core
generator and records coverage, generation counts, and branching masses for
actual hard children. No optimum oracle is an algorithm step.

Use the route for finite falsification of its joint macro, after the frozen
controls in `PRE-RUN-v1.json`. Neighboring `x0/` supplies independent original
controls; contact here burns that independence for certifying this design.

Output reports ordinary unaugmented rooted MAF blocks; residual cuts equal
minimum refining component count minus current live component count. Every
generated macro child has explicit paid cuts. Failure is a raised exception
or a named inadmissible/refuted outcome, never a success banner for zero cases.

Trust finite evidence only after the controls and comparator mutations execute,
the literal actual child passes both source orientations and tidying checks,
and all reconstruction partitions validate. Universal correctness, an improved
bound, and novelty remain OPEN pending fresh executable and Lean verification.

Run `develop.py` for its original pilot only when writing to a new receipt
path: its default output names the preserved v1 receipt. For original source
replay, preserve that receipt before using the default. `chain.py` similarly
names its v1 receipt. `minimize.py --version 1` replays the broader cut-only
policy; `--version 2` adds the earlier rule7 call-site exclusion. Preserve
existing receipts before either replay. The pin files record the actual
pre-execution registration and the policy amendment; originals are retained.

New capability index: `develop.py:core` generates source Lemma1 cut cores;
`develop.py:ownership_product` generates three survivor products;
`chain.py:assignment_cover` generates sequential multi-boundary source cuts;
`minimize.py:paid_chain_score` scores all overlap-edge choices and admits
only actual source/tidying states. These are development tools, not a tested
production FPT implementation. Their known-answer/negative controls and
exact reconstruction results are retained under `results/algorithm-macro-*`.
