# Unreviewed cheap/high pair proposal

Root scratch proposal, 2026-10-15. NOT a proved or accepted result. No X0,
independent replay, Lean construction or consumer review has been performed
for this proposal. It has not been sent to running authors. Preserve it for
a natural completed-phase handoff; do not silently insert it into a proof.

The named potential consumer is the binary mutually-clear pair case of the
main whole-source algorithm. A four-color whole-source generator list L has
actual cut costs d>=3 and a reviewed raw dyadic mass bound sum(2^-d)<=1/8.
Tentative simplification: if any output costs three, its positive dyadic
weight consumes the entire allowance, so the RAW LIST must be a singleton,
including multiplicity. Otherwise every cost is at least four and a dyadic
minimum-cost transfer should give sum(c^-d)<=2/c^4 for c>=2. This would avoid
having to prove a full prefix-profile grammar. Classifying the actual already
generated list avoids a separate optimum oracle or budget-monotonicity claim.

Tentative geometric bridge: an actual three-cut output has four original
components. With four nonempty colors and monochromatic output blocks, each
block must equal one whole color class. In an A-clear pair call these are
A1,A2,B,C. Both colors must be actual nonempty sectors; no assertion follows
for arbitrary unproved color-rank inputs.

Potential case argument, all conditional on exact disjoint-query accounting:

- If a parent is already a good agreement component, the binary E exchange
  might justify retaining it and emitting only the other clear cover.
- If both clear lists are high, their raw mass is at most 4/c^4.
- If an A-clear list is cheap and some A sector is bad, its singleton output
  leaves a genuine unresolved query. Its contribution might then acquire a
  unit of paid further progress. The other list is high or cheap.
- If a cheap A-clear list has both A sectors good but A itself is bad, the
  actual two-sector partition might witness local A optimum exactly one.
  Every B-clear output isolates A by mutual clarity. Its A query could then
  supply unit progress on every such output.
- Proposed resulting envelopes include c^-3+c^-4 and c^-3+2/c^5. Check by
  exact arithmetic that these are <=4/c^4 on the needed base interval before
  any claim. Combined with the two endpoint unit branches, the intended
  previously studied expression is 2/c+4/c^4 at the pinned c=233/100.

Essential missing consumer proofs: original two-sector source partition and
actual local restriction agreement; original-source E exchange to final
monochromatic refinement; exact query budget identities and additive query
work; all actual branch costs versus the recursion's remaining parameter;
termination and complete prior-rule/state selection. The source generator
does not itself supply those facts. Even a valid local envelope would not
establish the complete faster algorithm or novelty.

Future runtime-review question, NOT a defect finding: if a generator is called
on a whole original source with a budget that includes already-paid parent
cuts, a coarse O(poly(n)*2^B) generation bound needs explicit conversion to
the recursive remaining budget. Check the final state/call definitions, or a
rank/pruning/normalization argument, before using the bound in a recurrence.
