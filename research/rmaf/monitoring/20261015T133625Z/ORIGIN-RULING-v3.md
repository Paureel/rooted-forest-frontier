# Producer and source ruling

All 540 entries of the released v3 manifest matched their SHA256 pins. The review copied 396 nonbinary payloads and excluded 144 scientific .olean entries. All 143 positive scientific modules were rebuilt with the local Lean wrapper from those exact source bytes in a new isolated directory. The only external import roots are the bundled Std and Lean libraries. No live outside scientific source or copied scientific olean entered the rebuild.

The final producer audit enumerates every requested scientific module's stored ModuleData.constants array before name coalescing. It records actual producer and ordinal, actual ConstantInfo kind/type/body, recursor-rule bodies and inductive/constructor metadata, direct dependencies, direct axiom references and resolved origin/record separately. Full exact expressions are retained as rooted syntax DAGs with constructor tags, ordered children, levels, exact Name data, binder annotations, metadata and literals. ExprStructEq/Expr.equal handles hash collisions with structural equality; the alpha-equivalent Expr BEq is not an exactness certificate.

The audit contains 4977 stored declaration occurrences, 4938 unique stored names and 4938 resolved scientific names across all 143 producers. The 39 excess occurrences reflect coalescing and are retained. The inventory includes 571 private occurrences. Direct scientific custom axioms and unresolved actual dependencies are zero. The resolved-name axiom union is exactly Classical.choice, Quot.sound and propext; direct axiom references in actual type/body/recursor-rule expressions are propext. Every actual ConstantInfo kind was inspected, including unused, private and generated declarations. `DECLARATION-INDEX-v1.json` maps each occurrence to its full record and exact type/body digests.

All 126702 declaration-to-direct-dependency entries have both a resolved origin and stored producer candidates; dependency names are counted once per stored declaration. ModuleData also lists 1527 extra generated-name occurrences. Of these, 152 have resolved kernel ConstantInfo and are already represented in the stored inventory; 1375 have no kernel ConstantInfo type/body. Those IR-only auxiliaries retain their known producer names in `KERNEL-IR-SCOPE-v1.json`. Their compiled bodies are outside this accepted kernel proof inventory, and compiled IR/machine semantics remain unaccepted. The audit claims no complete machine-code inventory.

Seven actual stored bodies differ from the bodies resolved under the same names. Every pair has the same ConstantInfo kind and exact type. The retained names are `RMAF.rootedSpan.eq_def`, `RMAF.minimalVertices.eq_def`, `RMAF.pairwiseEmbeddings.eq_def`, `Universal233.CoreProgram.erase.eq_def`, `Universal233.CoreProgram.groups.eq_def`, `GenericForest.jobs.eq_def` and `List.all.eq_def`, produced respectively in Bridge, Bridge, Bridge, EraseLift, Branches, ForestQueries and ForestProgramControls. These are explicit proof-body differences, not raw exact matches; both actual and resolved bodies remain in the records. Fresh source compilation and zero custom-axiom results apply to the actual producer occurrences, rather than relying on the selected resolved theorem alone.

The exact type of `GenericForest.exact_of_ordinary` has only two explicit binders, ordinary and ho, no universe parameters and no hidden implicit/typeclass hypothesis. The executable `GenericForest.solve` scientific dependency closure contains 193 names when taking the union of all actual stored dependencies, including termination/proof dependencies. It excludes OrdinaryIH, DisjointExact, the finite fixture table, RMAF.solve, assignments and blocks. The external ordinary callback remains an explicit parameter. The exactness theorem's proof separately consumes OrdinaryIH and supplies the derived disjoint theorem.

All 143 original sources were reconstructed by reversing only the declared complete import lines, and every reconstructed byte string matched its original source SHA256. Of these, 129 original/adapted sources are identical. The 14 changed imports were also compiled under each root's canonical module name with freshly compiled, explicitly recorded original dependency aliases. This comparison context is part of the evidence; no global universe of simultaneously colliding original short module names is assumed.

Eleven of the 14 import counterparts match all stored kind/type/body/directAX records exactly. GroupCost, GroupStateFacts and QuerySpecification have 23 stored declarations with differing generated hygienic Name components inherited from the renamed dependencies. Every changed leaf is retained in `adapter-name-classification-v1.json`. Under only the declared Partition→GroupPartition, State→GroupState and Caller→QueryCaller Name correspondences, all those leaves match; no number, constructor, binder annotation, public symbol or literal changes. Four deliberately changed non-Name/numeric/public/literal twins were rejected by that classifier. The raw comparisons remain unequal, and these three module comparisons receive a qualified generated-Name correspondence rather than an unqualified exact-body claim. No adapter difference or producer attribution remains unresolved.

The original boundary producer controls passed before candidate contact: a hostile same-named/same-typed custom axiom plus an own clean declaration was invisible to the merged resolved-direct-axiom check and was caught in the stored producer array. Missing/duplicate/forged-total/resolved-only/private/unresolved controls and exact byte/body adapters passed. After raw proof repr caused a measured timeout, the lossless DAG format was requalified on the same separately versioned controls and a binder-preservation/false-alpha-collapse plant. Those later representation checks are post-contact checks. The original 88-payload READY and its expectations remain unchanged.
